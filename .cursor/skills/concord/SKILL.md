## Что это за проект

**Concord** — веб-система согласования документов через голосование. Автор создаёт согласование с разделами; согласователи голосуют Да/Нет; при отказе обязателен комментарий.

### Сущности

```
Согласование (Agreement)
  └── Раздел (Section) × N
        ├── Информационные блоки (text, links, files, gallery, code)
        ├── Блок согласования (всегда последний)
        └── Участники (к разделу, не ко всему согласованию)
```

### Роли

| Роль | Возможности |
|------|-------------|
| **Автор** | Создаёт, запускает; редактирует до запуска; корректирует разделы после (сброс голосов) |
| **Согласователь** | Голосует по разделам; голос неизменяем |
| **Гость** | По ссылке — только чтение блоков, без голосования |

### Статусы

`draft` → `awaiting` → `completed` / `expired` → `archived` | `deleted`

### Бизнес-правила (критичные)

1. Раздел согласован только если **все** участники проголосовали «Да»
2. Согласование завершено если **все** разделы согласованы или дедлайн
3. После дедлайна голоса не принимаются; голос **неизменяем**
4. Участники — к **разделам**; комментарий к отказу виден **только автору**
5. Корректировка раздела → сброс голосов + уведомление
6. Архивация через **2 недели** после завершения

## Workflow сборки

```
Прогресс:
- [ ] 1. Инфра: make up, bin/artisan migrate (см. engine.md)
- [ ] 2. БД Concord: миграции по reference.md
- [ ] 3. API в Zen.Act: act.api + сервисы
- [ ] 4. Jobs: отложенный запуск, архивация, уведомления
- [ ] 5. Vue в resources/act_app/: экраны по Figma
- [ ] 6. Проверка MVP-сценариев
```

### Шаг 1 — Инфраструктура

Не создавать отдельный `backend/`/`frontend/`. Использовать движок:

```bash
make up
cp php/.env.example php/.env   # при первом запуске
./bin/artisan october:migrate
cd php/plugins/zen/act && npm ci && npm run serve
```

### Шаг 2 — База данных

15 таблиц — [reference.md](reference.md#database). Миграции в плагине Zen.Act (`updates/`).

### Шаг 3 — API

Контракт из `vc/concord/План реализации - Backend.md` → реализовать как `act.api` классы. Список endpoints: [reference.md](reference.md#api).

Сервисы: `AgreementService`, `SectionService`, `VoteService`, `FileService`, `NotificationService`.

### Шаг 4 — Frontend

Vue 3 в `php/plugins/zen/act/resources/act_app/`. Stores (Pinia), компоненты блоков, роутинг SPA.

**UI:** сверять с Figma и [figma-ui.md](figma-ui.md) (решения по экранам). Тёмная тема — CSS-переменные.

### Шаг 5 — MVP-сценарии

1. Регистрация → подпись → согласование с разделами
2. Участники → запуск → уведомления
3. Голосование Да/Нет + комментарий при отказе
4. Завершение при единогласии
5. Корректировка раздела → сброс голосов
6. Дедлайн → просрочка
7. Дублирование, избранное, поиск, гостевая ссылка
