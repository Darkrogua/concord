# Бизнес-логика проекта "Согласование"

## Основная концепция

Система для согласования документов через голосование. Автор создает согласование с разделами, согласователи голосуют по каждому разделу (Да/Нет), при отказе обязателен комментарий с причиной.

## Роли пользователей

### Автор
- Создает согласования
- Может редактировать согласование только до запуска
- Может корректировать разделы при активном согласовании (после запуска)
- При корректировке раздела все голоса по этому разделу сбрасываются
- Участники, чьи голоса сброшены, получают уведомление о необходимости проголосовать повторно
- Видит результаты голосования в реальном времени
- Видит комментарии к отказам
- Может удалять согласования (мягкое удаление в корзину)
- Может архивировать согласования вручную
- Может повторно запустить согласование после завершения (с редактированием или без)

### Согласователь
- Голосует по разделам, к которым прикреплен
- Может проголосовать по одному разделу за раз
- Голос фиксируется и не может быть изменен
- Видит результаты голосования других участников (если включена видимость в настройках раздела)
- Автор также может быть согласователем

### Гость
- Пользователь без регистрации, получивший ссылку на согласование
- Может только читать информационные блоки разделов
- Не видит результаты голосования
- Не может голосовать

## Структура согласования

### Согласование
- Минимум один раздел, может быть несколько
- Параметры согласования:
  - Название
  - Описание
  - Дедлайн (обязательно)
  - Правила завершения: все разделы должны быть согласованы (единогласно)
  - Дата публикации (для отложенного запуска)
  - Проект/категория (опционально, для фильтрации)

### Раздел
- Содержит информационные блоки и блок согласования в конце
- Настройки раздела:
  - Наименование
  - Участники (прикрепленные согласователи)
  - Условия завершения: все участники должны согласовать (единогласно)
  - Видимость результатов: участники видят/не видят друг друга
  - Показывать результаты: до/после голосования участника
  - Важность и видимость раздела (на v2)

### Информационные блоки
Типы блоков:
1. Текстовый блок (форматирование, заголовки, списки, ссылки)
2. Блок со ссылками
3. Блок с файлами (до 50 МБ, популярные офисные форматы)
4. Блок с картинками
5. Блок с кодом

### Блок согласования
- Всегда идет последним в разделе
- Получает голос (Да/Нет) от участников раздела
- При отказе обязателен комментарий (до 500 символов, виден только автору)

## Процесс работы

### Создание согласования
1. Автор создает согласование, добавляет разделы
2. Заполняет информационные блоки в разделах
3. Прикрепляет согласователей к конкретным разделам
4. Настраивает параметры (дедлайн, правила завершения)
5. Может установить дату публикации для отложенного запуска
6. Сохраняет как черновик

### Запуск согласования
- Автор запускает согласование вручную или устанавливает дату публикации
- При запуске отправляются уведомления всем прикрепленным согласователям
- Согласование переходит в статус "Ждет согласования"
- Отложенные согласования запускаются автоматически в указанную дату
- До публикации автор может редактировать все что угодно

### Голосование
- Согласователь читает раздел, видит информационные блоки
- Голосует Да/Нет в блоке согласования
- При отказе обязательно указывает причину (комментарий)
- Может проголосовать по одному разделу за раз
- Голос фиксируется и не может быть изменен
- Видит результаты других участников (если включена видимость)
- Если автор корректирует раздел при активном согласовании, все голоса по этому разделу сбрасываются
- Участники получают уведомление о необходимости проголосовать повторно

### Завершение согласования
- Раздел считается согласованным, если все прикрепленные участники проголосовали "Да"
- Согласование считается завершенным, если все разделы согласованы
- Автоматическое завершение при достижении условий
- После дедлайна голоса не принимаются
- Те, кто не проголосовал до дедлайна, видят статус "завершено" или "просрочено"
- Если дедлайн истек и не все проголосовали, документ не будет согласован

### После завершения
- Определяется статус: согласовано/не согласовано
- Автор может повторно запустить согласование (с редактированием или без)
- У участников отображается как завершенное с результатом
- Через 2 недели автоматически уходит в архив
- Автор может вручную архивировать

## Статусы согласования

1. **Черновик** - создано, но не запущено
2. **Ждет согласования** - запущено, идет голосование
3. **Завершено** - согласовано/не согласовано
4. **Просрочено** - дедлайн истек
5. **Архив** - завершенные согласования (автоматически через 2 недели или вручную)
6. **Корзина** - мягко удаленные согласования (можно восстановить)

## Мульти-подпись

- Пользователь может иметь несколько "подписей" (контекстов)
- Аналогия с Figma: рабочий, личный, семейный и т.д.
- В интерфейсе всегда отображается активная подпись
- Все данные и действия происходят от имени активной подписи
- Позволяет группировать согласования по контекстам

## Группы

### Группа пользователей
- Список пользователей под одним названием
- Создает любой зарегистрированный пользователь
- Позволяет быстро добавлять пользователей к разделу согласования
- Ускорение заполнения

### Группа согласований
- Список согласований, собранных по критериям
- Критерии: автор, важность, входящие, срочность, избранное, архив
- По умолчанию у пользователей есть группы:
  1. Входящие
  2. Исходящие (созданные пользователем)
  3. Запущенные
  4. Все (кроме корзины)
  5. Избранное
  6. Корзина (мягко удаленные)
  7. Завершенные

## Фильтрация и поиск

### Фильтр согласования
- Временный фильтр, применяется к группе согласований
- Можно фильтровать по: дата, важность, автор, статус, проект и т.д.
- Фильтр можно сохранить, и он превратится в группу согласований

### Поиск согласований
- Работает в выбранной группе согласований
- Если выбрана группа "Все", поиск идет по всем согласованиям
- Поиск по: названиям, авторам, названиям разделов
- Без поиска по содержимому файлов

### Сортировка согласований
- По новизне, важности, скорому завершению
- Применяется в рамках группы согласований
- Если выбрана группа "Все", сортировка применяется ко всем согласованиям

## Проект (категория)

- Аналогия с интернет-магазином: согласование = товар, проект = категория
- Если проект не указан, показываются все согласования
- Если проект выбран, показываются только согласования этого проекта
- Пока это просто дополнительный фильтр

## Избранное

- Пользователь может добавить согласование в избранное (звездочка)
- Быстрый доступ к важным согласованиям
- Отдельная вкладка "Избранное" с количеством

## Дублирование

### Дублирование согласования
- Копируется все: разделы, информационные блоки, прикрепленные согласователи
- НЕ копируются: результаты голосований, дата начала, дата окончания
- Обязательно нужно редактировать перед запуском

### Дублирование раздела
- Копируется раздел со всеми информационными блоками
- Копируются прикрепленные согласователи
- Можно редактировать дубликат

## Поделиться согласованием

- Генерируется публичная ссылка на согласование
- Не зарегистрированный пользователь (гость) - только чтение информационных блоков
- Зарегистрированный пользователь:
  - Если участник раздела - может голосовать в своем разделе
  - Если не участник - видит результаты, но не может голосовать

## Уведомления

- Автоматическая рассылка при запуске согласования
- Дополнительные уведомления:
  - В процессе голосований
  - При приближении дедлайна
  - После дедлайна
  - При корректировке раздела автором (сброс голосов, необходимость проголосовать повторно)
- Типы уведомлений в v1:
  - Push-уведомления
  - Email-уведомления
- В v2: Telegram-бот
- Пока нельзя отключать уведомления

## Напоминания

- Автоматические напоминания о важных событиях согласования
- Частота напоминаний пока не настраивается

## Удаление согласования

- Только автор может удалять согласование
- Мягкое удаление (в корзину)
- Можно восстановить из корзины

## Доступность согласования

- Настройка видимости согласования
- Участники согласования всегда видят его
- По ссылке:
  - Зарегистрированный пользователь (не участник) - видит результаты
  - Не зарегистрированный (гость) - видит только информационные блоки без результатов

## Комментарии

### Комментарии к отказу (v1)
- Обязательны при голосовании "Нет"
- До 500 символов
- Видны только автору

### Комментарии в согласованиях (v2)
- Участвуют только те, кто реально голосует, и автор
- Прочие люди их не видят

## Прикрепление файлов

- Файлы - это контент информационного блока конкретного раздела
- Ограничения: не более 50 МБ, популярные офисные форматы
- Можно скачивать файлы
- Локальное хранилище (v1)

## Режим день-ночь

- Переключение цветовой схемы интерфейса
- Настройка сохраняется для каждого пользователя

## Аккаунтинг (v1)

- Регистрация через email с верификацией
- Вход
- Восстановление пароля (нужно в v1)
- Удаление аккаунта

## Логирование

- Детальное логирование всех действий пользователей
- Кто создал, кто проголосовал, когда и т.д.
- Для аудита и отслеживания изменений

## Важные правила и ограничения

1. Раздел согласован только если ВСЕ участники проголосовали "Да"
2. Согласование завершено только если ВСЕ разделы согласованы
3. После дедлайна голоса не принимаются
4. Голос фиксируется и не может быть изменен
5. Автор может редактировать согласование только до запуска
6. Автор может корректировать разделы при активном согласовании (после запуска)
7. При корректировке раздела автором все голоса по этому разделу сбрасываются
8. Участники, чьи голоса сброшены, получают уведомление о необходимости проголосовать повторно
9. Участники прикрепляются к конкретным разделам, не ко всему согласованию
10. Автор видит результаты голосования в реальном времени
11. Комментарии к отказу видны только автору
12. Завершенные согласования автоматически архивируются через 2 недели
13. Автор может повторно запустить согласование после завершения
