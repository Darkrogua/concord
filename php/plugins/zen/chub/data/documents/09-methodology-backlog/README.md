# Ведение документации и бэклог

Короткий корневой файл репозитория намеренно содержит только входные сведения и отсылает к расширенным материалам. Детальные регламенты и длинные инструкции хранятся в общей документации проекта вне этого дерева; **здесь**, в админке, собрано то, что нужно разработчику для работы с Zen.Chub без переключения на внешние системы.

Бэклог продукта и технические предложения могут вестись в отдельных каналах команды; при принятии решения итог стоит отражать в этом разделе или в коде через комментарии и миграции, чтобы состояние системы было восстановимо по артефактам репозитория.

Соглашения по стилю кода, именованию и безопасности дополняют общий контекст: перед крупным рефакторингом сверяйтесь с принятыми в команде правилами и не смешивайте несвязанные изменения в одном изменении для упрощения ревью.
