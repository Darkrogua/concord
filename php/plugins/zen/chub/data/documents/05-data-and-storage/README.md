# Данные и хранилища

В Zen.Chub используются несколько уровней хранения, и их смешивание на уровне интуиции часто приводит к ошибкам при деплое и отладке.

**Основная реляционная база** (в проекте на MySQL) содержит таблицы с префиксом, согласованным с плагином: сущности реестра, каталог круизов, справочники, связи и вспомогательные структуры. Схема эволюционирует через миграции; нормализованные отношения и уникальные индексы описываются там, где это важно для целостности данных.

**JSON-файлы** в каталоге данных плагина хранят конфигурации, фрагменты, согласованные с поставкой кода, и не должны подменять собой данные, которые создают пользователи в админке, если иное явно не оговорено.

**Адресное пространство `storage` внутри плагина и приложения** предназначено для кешей, загрузок пользователей, сгенерированных файлов и служебных SQLite. Эти пути зависят от окружения и прав доступа процесса PHP.

При проектировании новой функции явно решите: данные живут в SQL, в JSON-поставке, во временном кеше файловой системы или в операционном SQLite из раздела про runtime.
