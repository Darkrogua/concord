# Маршрутизация и API

Для Zen.Chub реализован **динамический** маршрут HTTP API: запросы направляются к классам и методам по соглашению об именовании и конфигурации маршрутов плагина. Это позволяет добавлять точки интеграции без объявления каждого маршрута вручную в духе классического REST со статическим списком endpoints.

При разработке новых методов API важно соблюдать принятый в проекте контракт входных и выходных данных (часто JSON), учитывать авторизацию и недопустимость вызова служебных или отладочных классов из производственной среды без ограничений.

Отладочные или вспомогательные классы API должны быть явно отделены по назначению от стабильных контрактов для интеграций, чтобы при деплое можно было исключить лишнее с помощью конфигурации окружения.

Версионирование контрактов для внешних клиентов по возможности делайте явным: при ломающих изменениях координируйте обновление потребителей API заранее.
