### Механики смарт-контракта
1. ==Аккаунтинг== - Система хранения данных пользователей по ключу в приватной сессии
	1. **Свойство** - Подписи: У каждого пользователя может быть `1+` подписей, каждая из которых:
		1. **Свойство** - Имеет свой `uuid`
		2. **Механика** - Когда пользователь подписывает смарт контракт S подписью F создаётся транзакция `S:F`
		3. **Нюанс** - Запрос подписи бывает следующих типов
			1. **Тип** - Запрос любой подписи пользователя
			2. **Тип** - Запрос конкретной(ых) подписи(ей) пользователя
		4. **Нюанс** - Перед тем как запросить конкретные подписи пользователя, их нужно с начала добавить к себе в аккаунт, это можно сделать зайдя на страницу пользователя (по его нику) и в разделе "Подписи" выбрать те подписи которые пользователь опубликовал для всех (или для конкретных пользователей)
		5. **Механика** - Доступность подписей для пользователей это либо `FP_UUID+USER_UUID` либо `FP_UUID+*` (подпись доступна всем)
2. ==Менеджмент контента== (управление контентом внутри смарт-контракта)
	1. **Действие** - Создание блока контента
	2. **Действие** - Редактирование блока контента
	3. **Действие** - Перемещение блока контента в порядке сортировки
	4. **Действие** - Удаление блока контента
	5. **Действие** - Добавление запроса на подпись в блок контента
	6. **Нюанс** - Блоки контента могут иметь разные типы: Текст, Файл, Изображение, Видео, Скрипт, Триггер
	7. **Нюанс** - К каждому блоку контента можно подключить один или несколько запросов на подпись
3. ==Запрос на подпись== (элемент интерфейса в виде чекбокса)
	1. **Свойство** - У запроса на подпись есть свойство подписанты, где хранятся идентификаторы `uuid > 1` подписей пользователей которые могут изменить состояние чекбокса;
		1. Событие - Запрос подписи был выполнен (подписант подписал своей подписью)
	2. **Нюанс** - У каждого пользователя может быть больше одной подписи, у каждой из которых свой уникальный идентификатор uuid
4. ==Смарт-контракт== (базовая сущность)
	1. **Действие** - Создание смарт-контракта
	2. **Действие** - Конфигурирование смарт-контракта
		1. **Действие** - Формирование структуры контента (1. состав; 2. последовательность; 3. настройки.)
		2. **Действие** - Формирование реактивных механик (скрипты реагирующие на состояние смарт-контракта)
		3. **Действие** - Публикация смарт-контракта
			1. **Свойство** - Запрет изменений после запуска
			2. **Свойство** - Время действия смарт-контракта
	3. **Свойство** - Жизненный цикл смарт-контракта
		1. **Событие** - Смарт-контракт создан
		2. **Событие** - Смарт-контракт опубликован
		3. **Событие** - Смарт-контракт изменён
		4. **Событие** - Смарт-контракт выполнен
		5. **Событие** - Смарт-контракт удалён
5. ==Интерфейс== - PWA Приложение на Vue3
	1. **Компонент** - Блок аккаунта
		1. **Свойство** - Переход в настройки пользователя (кабинет)
		2. **Свойство** - Выбор активной подписи
	2. **Экран** - Дашборд: Список смарт-контрактов
		1. **Свойство** - Фильтрация
		2. **Свойство** - Сортировка
		3. **Свойство** - Поиск
	3. **Экран** - Смарт-контракт, существует в двух режимах
		1. **Режим** - Редактирование (Можно редактировать, имеются элементы управления)
		2. **Режим** - Превью (Посмотреть как выглядит без элементов управления)
		3. **Режим** - Публикация (опубликованный смарт-контракт)
