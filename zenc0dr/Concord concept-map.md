
### Базовое описание
Concord - Это Saas платформа для автоматизации контроля рабочих процессов, представленная в форме web-приложения распространяемого через web1.0/2.0, pwa, android-webview.

### Назначение и решаемые задачи
Основное назначение платформы: Интерфейс управления смарт-контрактами. Решаемые задачи:
- Приватное хранение данных в зашифрованном контейнере (смарт-контракте)
- Публикация смарт-контракта в сети (uuid-url)
- Организация процесса подписания смарт-контрактов множеством подписантов
- Управление жизненным циклом смарт-контрактов от создания до архивации

### Механики смарт-контракта
1. ==Аккаунтинг== - Система хранения данных пользователей по ключу в приватной сессии
	1. **Свойство** - Подписи: У каждого пользователя может быть `1+` подписей, каждая из которых:
		1. **Свойство** - Имеет свой `uuid`
		2. **Механика** - Когда пользователь подписывает смарт контракт S подписью F создаётся транзакция `S:F`
		3. **Нюанс** - Запрос подписи бывает следующих типов
			1. **Тип** - Запрос любой подписи пользователя
			2. **Тип** - Запрос конкретной(ых) подписи(ей) пользователя
		4. **Нюанс** - Перед тем как запросить конкретные подписи пользователя, их нужно с начала добавить к себе в аккаунт, это можно сделать зайдя на страницу пользователя (по его нику) и в разделе "Подписи" выбрать те подписи которые пользователь опубликовал для всех (или для конкретных пользователей)
		5. **Механика** - Доступность подписей для пользователей это либо `FP_UUID+USER_UUID` либо `FP_UUID+*` (подпись доступна всем)
		6. **Свойство** - Активная подпись: В интерфейсе всегда отображается активная подпись пользователя, все данные и действия происходят от имени активной подписи
		7. **Механика** - Регистрация и аутентификация: Регистрация через email с верификацией, вход, восстановление пароля, удаление аккаунта
	2. **Свойство** - Роли пользователей:
		1. **Тип** - Автор: Пользователь создающий смарт-контракты
			1. **Действие** - Создает смарт-контракты с блоками контента
			2. **Действие** - Может редактировать смарт-контракт только до публикации
			3. **Действие** - Может корректировать блоки контента при активном смарт-контракте (после публикации)
			4. **Механика** - При корректировке блока контента все подписи по запросам на подпись в этом блоке сбрасываются
			5. **Свойство** - Видит результаты подписания в реальном времени
			6. **Свойство** - Видит комментарии к отказам (видны только автору)
			7. **Действие** - Может удалять смарт-контракты (мягкое удаление в корзину)
			8. **Действие** - Может архивировать смарт-контракты вручную
			9. **Действие** - Может повторно запустить смарт-контракт после завершения (с редактированием или без)
			10. **Свойство** - Может видеть статистику по блокам контента (сколько подписано, сколько осталось)
			11. **Нюанс** - Автор также может быть подписантом
		2. **Тип** - Подписант: Пользователь который имеет право оставить свою подпись в смарт-контракте
			1. **Действие** - Подписывает запросы на подпись, к которым прикреплен
			2. **Действие** - Может подписать один запрос на подпись за раз
			3. **Свойство** - Подпись фиксируется и не может быть изменена
			4. **Свойство** - Видит результаты подписания других подписантов (если включена видимость в настройках блока контента)
			5. **Свойство** - Видит результаты подписания в запросе на подпись после своей подписи
			6. **Нюанс** - При подписании "Нет" обязательно указывает причину (комментарий)
			7. **Механика** - Если автор корректирует блок контента при активном смарт-контракте, получает уведомление о необходимости подписать повторно
		3. **Тип** - Гость: Пользователь без регистрации, получивший ссылку на смарт-контракт
			1. **Свойство** - Может только читать блоки контента
			2. **Свойство** - Не видит результаты подписания
			3. **Свойство** - Не может подписывать
			4. **Свойство** - Не видит список подписантов смарт-контракта
			5. **Свойство** - Доступ только по публичной ссылке на смарт-контракт
2. ==Менеджмент контента== (управление контентом внутри смарт-контракта)
	1. **Действие** - Создание блока контента
	2. **Действие** - Редактирование блока контента
	3. **Действие** - Перемещение блока контента в порядке сортировки
	4. **Действие** - Удаление блока контента
	5. **Действие** - Добавление запроса на подпись в блок контента
	6. **Действие** - Дублирование блока контента (копирование блока со всеми информационными данными и прикрепленными подписантами)
	7. **Нюанс** - Блоки контента могут иметь разные типы: Текст, Файл, Изображение, Видео, Скрипт, Триггер
		1. **Тип** - Текстовый блок: Выделение текста, смена размера заголовка, списки нумерованные и нет, ссылки, обычный текст, возможность добавления эмодзи
			1. **Свойство** - Имеет заголовок, возможность редактировать его создателем блока
			2. **Нюанс** - Если заголовок не прописывается создателем блока, то он не выводится для конечного пользователя
		2. **Тип** - Блок с файлами: Разрешенные форматы обычные документы xlsx, doc, json, pdf и т.д.
			1. **Свойство** - Ограничения: не более 50 МБ на файл
			2. **Действие** - Можно скачивать файлы
			3. **Свойство** - Отображается иконка типа файла рядом с названием
		3. **Тип** - Блок с изображениями (Галерея): Группа изображений, отображаемых вместе
			1. **Свойство** - Можно просматривать изображения в галерее
			2. **Свойство** - Подписи к изображениям опциональны
		4. **Тип** - Блок со ссылками: Форматированный вывод ссылок
			1. **Свойство** - Ссылки форматированы для удобного просмотра
			2. **Свойство** - Могут иметь превью страницы
			3. **Свойство** - Кликабельные элементы
		5. **Тип** - Блок с кодом: Отображение кода
			1. **Свойство** - Сохранение исходного форматирования кода
			2. **Свойство** - Подсветка синтаксиса (если поддерживается)
			3. **Действие** - Кнопка копирования кода
	8. **Нюанс** - К каждому блоку контента можно подключить один или несколько запросов на подпись
	9. **Свойство** - Настройки блока контента:
		1. **Свойство** - Наименование блока
		2. **Свойство** - Подписанты (прикрепленные подписанты к запросам на подпись в блоке)
		3. **Свойство** - Условия завершения: все подписанты должны подписать (единогласно)
		4. **Свойство** - Видимость результатов: подписанты видят/не видят друг друга
		5. **Свойство** - Показывать результаты: до/после подписания подписантом
		6. **Нюанс** - Разделы можно сворачивать/разворачивать
		7. **Нюанс** - Разделы отображаются лентой сверху вниз (вертикальная прокрутка)
3. ==Запрос на подпись== (элемент интерфейса в виде чекбокса)
	1. **Свойство** - У запроса на подпись есть свойство подписанты, где хранятся идентификаторы `uuid > 1` подписей пользователей которые могут изменить состояние чекбокса
		1. **Событие** - Запрос подписи был выполнен (подписант подписал своей подписью)
		2. **Событие** - Запрос подписи был отклонен (подписант подписал "Нет")
	2. **Нюанс** - У каждого пользователя может быть больше одной подписи, у каждой из которых свой уникальный идентификатор uuid
	3. **Свойство** - Отображает вопрос "Подписать?" с вариантами "Да" и "Нет"
	4. **Механика** - При подписании "Нет" обязателен комментарий с причиной
		1. **Свойство** - Максимальная длина комментария: 500 символов
		2. **Свойство** - Комментарий виден только автору смарт-контракта
		3. **Свойство** - Подписанты не видят комментарии других подписантов
	5. **Свойство** - После подписания подписант видит результаты в том же запросе на подпись
	6. **Свойство** - Запрос на подпись остается с результатом после подписания
	7. **Свойство** - Показывает информацию о дедлайне и подписантах
	8. **Свойство** - Результаты подписания других подписантов отображаются (если включена видимость в настройках блока контента)
	9. **Нюанс** - Может подписать один запрос на подпись за раз
	10. **Нюанс** - Подпись фиксируется сразу после отправки и не может быть изменена
	11. **Нюанс** - После дедлайна подписи не принимаются
4. ==Смарт-контракт== (базовая сущность)
	1. **Действие** - Создание смарт-контракта
		1. **Свойство** - Минимум один блок контента, может быть несколько
		2. **Действие** - Сохранение как черновик
	2. **Действие** - Конфигурирование смарт-контракта
		1. **Действие** - Формирование структуры контента (1. состав; 2. последовательность; 3. настройки.)
		2. **Действие** - Формирование реактивных механик (скрипты реагирующие на состояние смарт-контракта)
		3. **Действие** - Прикрепление подписантов к конкретным блокам контента
			1. **Механика** - Добавление подписантов по одному через поиск по всем пользователям
			2. **Механика** - Выбор группы пользователей для быстрого добавления
			3. **Механика** - Создание новой группы пользователей
			4. **Нюанс** - Подписанты прикрепляются к конкретным блокам контента, не ко всему смарт-контракту
			5. **Нюанс** - Один подписант может быть прикреплен к нескольким блокам контента одного смарт-контракта
		4. **Действие** - Публикация смарт-контракта
			1. **Свойство** - Запрет изменений после публикации (кроме корректировки блоков контента)
			2. **Свойство** - Время действия смарт-контракта (дедлайн)
			3. **Свойство** - Дата публикации (для отложенного запуска)
			4. **Механика** - При публикации отправляются уведомления всем прикрепленным подписантам
			5. **Механика** - Отложенные смарт-контракты запускаются автоматически в указанную дату
	3. **Свойство** - Параметры смарт-контракта:
		1. **Свойство** - Название
		2. **Свойство** - Описание
		3. **Свойство** - Дедлайн (обязательно)
		4. **Свойство** - Правила завершения: все блоки контента должны быть подписаны (единогласно)
		5. **Свойство** - Дата публикации (для отложенного запуска)
		6. **Свойство** - Проект/категория (опционально, для фильтрации)
		7. **Свойство** - Автор
		8. **Свойство** - Дата создания
		9. **Свойство** - Дата завершения
		10. **Свойство** - Количество блоков контента
		11. **Свойство** - Количество подписанных блоков контента
	4. **Свойство** - Жизненный цикл смарт-контракта (статусы):
		1. **Статус** - Черновик: создано, но не опубликовано
		2. **Статус** - Ждет подписания: опубликовано, идет процесс подписания
		3. **Статус** - Завершено: подписано/не подписано
		4. **Статус** - Просрочено: дедлайн истек
		5. **Статус** - Архив: завершенные смарт-контракты (автоматически через 2 недели или вручную)
		6. **Статус** - Корзина: мягко удаленные смарт-контракты (можно восстановить)
	5. **Свойство** - События жизненного цикла смарт-контракта:
		1. **Событие** - Смарт-контракт создан
		2. **Событие** - Смарт-контракт опубликован
		3. **Событие** - Смарт-контракт изменён
		4. **Событие** - Смарт-контракт выполнен
		5. **Событие** - Смарт-контракт удалён
	6. **Механика** - Правила завершения:
		1. **Правило** - Блок контента считается подписанным, если все прикрепленные подписанты подписали "Да"
		2. **Правило** - Смарт-контракт считается завершенным, если все блоки контента подписаны
		3. **Правило** - Автоматическое завершение при достижении условий
		4. **Правило** - После дедлайна подписи не принимаются
		5. **Правило** - Если дедлайн истек и не все подписали, смарт-контракт не будет подписан
	7. **Действие** - Дублирование смарт-контракта
		1. **Механика** - Копируется все: блоки контента, информационные данные, прикрепленные подписанты
		2. **Нюанс** - НЕ копируются: результаты подписания, дата начала, дата окончания
		3. **Нюанс** - Обязательно нужно редактировать перед публикацией
	8. **Действие** - Удаление смарт-контракта
		1. **Механика** - Мягкое удаление (в корзину)
		2. **Свойство** - Удаленное автором смарт-контракт будет скрыто из списка, но в конечном итоге будет удалено полностью через n дней
		3. **Действие** - Можно восстановить из корзины
	9. **Свойство** - Доступность смарт-контракта:
		1. **Свойство** - Участники смарт-контракта всегда видят его
		2. **Свойство** - По публичной ссылке: зарегистрированный пользователь (не участник) - видит только блоки контента без результатов
		3. **Свойство** - По публичной ссылке: не зарегистрированный (гость) - видит только блоки контента без результатов
	10. **Действие** - Поделиться смарт-контрактом
		1. **Механика** - Генерируется публичная ссылка на смарт-контракт
		2. **Нюанс** - Не зарегистрированный пользователь (гость) - только чтение блоков контента
		3. **Нюанс** - Зарегистрированный пользователь: если участник блока контента - может подписывать в своем блоке; если не участник - видит только блоки контента без результатов, подписывать не может
5. ==Интерфейс== - PWA Приложение на Vue3
	1. **Компонент** - Блок аккаунта
		1. **Свойство** - Переход в настройки пользователя (кабинет)
		2. **Свойство** - Выбор активной подписи
	2. **Экран** - Дашборд: Список смарт-контрактов
		1. **Свойство** - Фильтрация смарт-контрактов
			1. **Механика** - Временный фильтр, применяется к группе смарт-контрактов
			2. **Свойство** - Можно фильтровать по: дата, важность, автор, статус, проект и т.д.
			3. **Действие** - Фильтр можно сохранить, и он превратится в группу смарт-контрактов
		2. **Свойство** - Сортировка смарт-контрактов
			1. **Механика** - По новизне, важности, скорому завершению
			2. **Механика** - Применяется в рамках группы смарт-контрактов
			3. **Механика** - Если выбрана группа "Все", сортировка применяется ко всем смарт-контрактам
		3. **Свойство** - Поиск смарт-контрактов
			1. **Механика** - Работает в выбранной группе смарт-контрактов
			2. **Механика** - Если выбрана группа "Все", поиск идет по всем смарт-контрактам
			3. **Свойство** - Поиск по: названиям, авторам, названиям блоков контента
			4. **Нюанс** - Без поиска по содержимому файлов
		4. **Свойство** - Группы смарт-контрактов
			1. **Механика** - Список смарт-контрактов, собранных по критериям
			2. **Свойство** - Критерии: автор, важность, входящие, срочность, избранное, архив
			3. **Свойство** - По умолчанию у пользователей есть группы:
				1. Входящие
				2. Исходящие (созданные пользователем)
				3. Запущенные
				4. Все (кроме корзины)
				5. Избранное
				6. Корзина (мягко удаленные)
				7. Завершенные
		5. **Свойство** - Проект (папка)
			1. **Механика** - Смарт-контракты всегда закреплены за каким-либо проектом
			2. **Механика** - Зарегистрированный пользователь может переключаться между проектами и видеть смарт-контракты только этого проекта
			3. **Нюанс** - Если проект не указан, показываются все смарт-контракты
			4. **Нюанс** - Если проект выбран, показываются только смарт-контракты этого проекта
		6. **Свойство** - Избранное
			1. **Действие** - Пользователь может добавить смарт-контракт в избранное (звездочка)
			2. **Свойство** - Быстрый доступ к важным смарт-контрактам
			3. **Свойство** - Отдельная вкладка "Избранное" с количеством
		7. **Компонент** - Карточка смарт-контракта (в списке)
			1. **Свойство** - Отображает ID, название, дату создания, автора
			2. **Свойство** - Показывает статус смарт-контракта
			3. **Свойство** - Иконка пламени меняет цвет в зависимости от близости дедлайна
			4. **Свойство** - Прогресс: "X/Y" (количество подписанных блоков контента из общего числа)
			5. **Свойство** - Прогресс-бар показывает процент подписанных блоков контента
			6. **Свойство** - Иконки действий: избранное, копирование, редактирование
	3. **Экран** - Смарт-контракт, существует в трех режимах
		1. **Режим** - Редактирование (Можно редактировать, имеются элементы управления)
		2. **Режим** - Превью (Посмотреть как выглядит без элементов управления)
		3. **Режим** - Публикация (опубликованный смарт-контракт)
		4. **Свойство** - Особенности отображения:
			1. **Свойство** - Блоки контента отображаются лентой сверху вниз (вертикальная прокрутка)
			2. **Свойство** - Блоки контента можно сворачивать/разворачивать
			3. **Свойство** - Все пользователи видят все блоки контента
			4. **Свойство** - Если пользователь является подписантом в блоке контента, он видит запрос на подпись
			5. **Свойство** - Если пользователь не является подписантом блока контента, он видит только блоки контента без запроса на подпись
			6. **Свойство** - Для автора: видит все блоки контента и запросы на подпись, видит результаты подписания в реальном времени, видит комментарии к отказам, может видеть статистику по блокам контента
	4. **Компонент** - Группа пользователей
		1. **Свойство** - Список пользователей под одним названием
		2. **Действие** - Создает любой зарегистрированный пользователь
		3. **Механика** - Позволяет быстро добавлять пользователей к блоку контента смарт-контракта
		4. **Свойство** - Ускорение заполнения
		5. **Свойство** - Управление группами пользователей можно в двух местах: при создании смарт-контракта и в настройках приложения
	5. **Компонент** - Нижняя навигационная панель
		1. **Свойство** - Всегда видна на всех экранах
		2. **Свойство** - Пять вкладок: Смарт-контракты, Настройки, Создать, Уведомления, Профиль
		3. **Свойство** - Центральная кнопка "Создать" может быть больше остальных
		4. **Свойство** - Уведомления могут иметь бейдж с количеством непрочитанных
		5. **Свойство** - Активная вкладка выделена фиолетовым цветом
	6. **Компонент** - Режим день-ночь
		1. **Свойство** - Переключение цветовой схемы интерфейса
		2. **Свойство** - Настройка сохраняется для каждого пользователя
6. ==Уведомления==
	1. **Механика** - Автоматическая рассылка при публикации смарт-контракта
	2. **Свойство** - Дополнительные уведомления:
		1. **Тип** - В процессе подписания
		2. **Тип** - При приближении дедлайна
		3. **Тип** - После дедлайна
		4. **Тип** - При корректировке блока контента автором (сброс подписей, необходимость подписать повторно)
	3. **Свойство** - Типы уведомлений в v1:

		2. **Тип** - Email-уведомления
	4. **Свойство** - В v2: Telegram-бот
	5. **Нюанс** - Пока нельзя отключать уведомления
	6. **Свойство** - Выделение "Важных" уведомлений
